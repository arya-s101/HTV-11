# Change PRD v3 — Short base game, no damage spotting, layout and bug fixes

> Applies on top of `PRD.md` (v2 + game-show section 5.10). Where this document conflicts with `PRD.md`, **this document wins**. Everything not mentioned here stays as specified in `PRD.md`.

## Summary of changes

1. **Two modes:** a short **Base game** containing only the vital lessons, and an opt-in **Extended game** with the full journey.
2. **Remove all interactive damage spotting** (point-and-click issue hunting and tap-the-defect photo walkthroughs). The lessons stay as quick game-show questions.
3. **Fix alignment issues and other bugs** via a structured audit, then fixes.
4. **Stat cards:** after each answered question, a large, skippable card shows one relevant, sourced Toronto statistic.

Suggested order: 3 (stabilize) → 2 (remove) → 1 (restructure). Removing and restructuring on top of a buggy layout makes the bugs harder to isolate.

## Change 1 — Base game and Extended game

### Goal
A first-time player finishes the Base game in **about 2–3 minutes at normal text speed** and gets the core lessons. Anyone who wants more can choose the Extended game from the start screen or the end screen.

### Base game (default)

Stage 2 (First job) only. Five beats, each one round of the game show:

| # | Round | What happens | Lesson kept |
|---|---|---|---|
| 0 | Quick character | Creator with a **Randomize** button and **Start** reachable in one tap; full customization optional | — |
| 1 | Spot the Fake | 3 illustrative listings, flag the scam; one is detectable via the CMHC benchmark | Scam red flags; "too good to be true" vs. the benchmark |
| 2 | Pick Your Place | 2 offers (hero demo values, `PRD.md` §6); player flags what to verify; reveal shows burden, fare, hours and one unknown cost | Hidden costs; cash vs. time; no fake fare savings |
| 3 | Move-In Day | One multiple-choice question: what do you do before unpacking? Correct answer (photograph everything) earns the photos receipt | Document the unit at move-in |
| 4 | Something Breaks | One event (e.g. no heat); player picks the response and who to contact; the photos receipt (or its absence) changes the outcome | Requests in writing; who to contact; which level of government |
| 5 | Final | Rental readiness report card + one candidate question + **"Play the Extended game"** button | Civic layer |

Base game rules:
- **No negotiation, no LLM calls.** The Base game works fully offline from the API.
- Difficulty picker available (Easy default).
- No life-stage progression; the character stays at Stage 2.
- Base report card scores only what the Base rounds test.

### Extended game (opt-in)

Selectable on the start screen and from the Base report card. Contains everything in `PRD.md` §5.3, with Change 2 applied:

- All 8 journey phases: Search, Viewing (as questions, see Change 2), Apply, Negotiate (LLM landlord + scripted fallback), Read the Lease, Move In, Live There (multiple events), Move Out.
- Difficulty selection, lifelines, receipts carried across phases.
- Further life stages as they become ready (each only once its content is sourced).
- Extended report card covers all phases.

Starting Extended after finishing Base keeps the same character and offers to skip rounds already played.

### Implementation notes
- Add `mode: "base" | "extended"` to game state. A mode config lists which rounds run, in order: `config/modes.ts` (or `.json`). Rounds are not duplicated per mode; Base reuses Extended's round modules with fewer items (e.g. 3 listings instead of the full feed, 1 event instead of several).
- Demo preset uses Base mode.

### Supersedes in PRD.md
- §10 "Demo path" → now the Base game, about 2–3 minutes.
- §10 tier table → Tier 1 = Base game end to end (Change 1 table) + game-show shell. Tier 1b/1c/2 = Extended content.

### Acceptance criteria
- [ ] Start screen offers **Play** (Base) and **Extended**.
- [ ] Base runs exactly rounds 0–5 above; completes in ≤3 minutes at normal text speed with the demo preset (time it).
- [ ] Base makes zero LLM/API calls (verify in network log).
- [ ] Move-In Day answer sets the photos receipt; Something Breaks has a different outcome with vs. without it.
- [ ] Base report card has a working "Play the Extended game" button that keeps the character.
- [ ] Extended runs all 8 phases with Change 2 applied.

## Change 2 — Remove interactive damage spotting

### What to remove
- **Viewing phase:** the point-and-click pixel apartment where the player hunts for issues (mould, pests, water pressure, smoke alarm, windows, outlets), including its timer, hit areas and found/missed tracking.
- **Move-in phase:** the photo walkthrough where the player taps rooms/defects to "photograph" them.
- Any assets, components, state fields, tests and report-card categories that exist only for those mechanics (e.g. "viewing issues found").

### What replaces it
The lessons stay, delivered as normal game-show rounds (big buttons, one idea per screen):
- **Viewing (Extended only):** 2–3 quick questions, e.g. "What should you check during a viewing?" with 3–4 answer buttons. Correct answers draw on the sourced viewing-checklist content.
- **Move in:** the single multiple-choice question in Base round 3. Extended can add one more (tenant insurance).
- The photos receipt is earned by the correct answer, not by tapping.

### Supersedes in PRD.md
- §5.3 rows 2 (Viewing) and 6 (Move in): mechanics become multiple-choice questions.
- §5.10: drop "timers on viewing" (keep the Spot the Fake timer).
- §10 Tier 1 checks: delete "Phase 2: at least 4 findable issues; missed issues reappear as consequences" and "Phase 6: photos become receipts" as written; replaced by Change 1 criteria.
- Report card (§5.9): replace "Unknown costs and viewing issues found" with "Unknown costs found".

### Acceptance criteria
- [ ] No screen asks the player to click or tap on a picture to find damage or defects.
- [ ] Removed components, assets and state fields are deleted, not just hidden (no dead code paths, no unused imports).
- [ ] Viewing and move-in lessons are still taught via question rounds, each with a sourced ContentItem.
- [ ] All tests pass after removal; tests for removed mechanics are deleted.

## Change 3 — Fix alignment issues and other bugs

The specific bugs were seen on the team's machine and aren't listed here yet. **Claude Code: run the audit below first, write findings to `BUGS.md`, then fix.** Team members add anything they've seen to the Known bugs table.

### Audit procedure
1. Run the app locally. Play the full Base game and the full Extended game.
2. Check every screen at **375×667 (phone), 768×1024 (tablet), 1280×800 and 1920×1080 (desktop)**, plus browser zoom at 200%.
3. Repeat once with reduced motion on and once with text speed "instant".
4. Watch the browser console the whole time; every error or warning is a bug.
5. Log each issue in `BUGS.md` with screen, viewport, expected vs. actual, and a fix status.

### Layout checklist (check each item on each screen)
- [ ] Host, podium, character, text box and buttons are centred and never overlap each other at any viewport.
- [ ] The text box **reserves its final height** so line-by-line text doesn't shift buttons or content down as it appears.
- [ ] Long lines wrap inside the text box; nothing overflows or clips; no horizontal page scroll.
- [ ] Answer buttons are equal width in a row, aligned, at least 44×44px tap targets, and stack cleanly on phones.
- [ ] Score, lifelines and receipts HUD stay pinned and never cover the text box or buttons (respect mobile safe areas).
- [ ] Animated number counters use tabular figures and fixed width so digits don't jitter.
- [ ] Pixel sprites scale at integer multiples with `image-rendering: pixelated`; never blurry or stretched.
- [ ] Transitions end with every element back at its resting position (no leftover transforms or offsets).
- [ ] Provenance chips and "Why?" drawers open and close without shifting the layout behind them.
- [ ] Fonts load before first text appears (no flash of fallback font changing line breaks mid-animation).

### Behaviour checklist
- [ ] Tap/click/keyboard: first press finishes the current line, second press advances; double-taps never skip a question.
- [ ] Answer buttons disable after a choice so a second tap can't score twice.
- [ ] Going back, refreshing or restarting mid-round doesn't leave stale score, receipts or timer state.
- [ ] Timers stop when a round ends, when the tab is hidden, and on restart.
- [ ] Sound toggle state persists across rounds; nothing plays while muted.
- [ ] Seeded runs are reproducible: same seed, same listings and events.
- [ ] Calc tests from `PRD.md` §10 still pass.

### Acceptance criteria
- [ ] `BUGS.md` exists with every audited issue and its status.
- [ ] Every item in the Known bugs table and the audit is fixed or explicitly deferred with a reason.
- [ ] No console errors or warnings during a full Base and Extended run.
- [ ] Layout checklist passes at all four viewports and 200% zoom.
- [ ] Regression check: a quick replay of the Base demo preset after all fixes.

## Change 4 — Stat cards after each answer

### Goal
After the answer feedback, show one real number that makes the lesson land ("this actually happens"), in a calm, big, glanceable way. Never a chart wall, never required reading.

### Placement
`answer → feedback (correct/wrong + fix) → stat card → next question`

### Design
- **One stat per card.** A big animated number (the largest thing on screen), a short label underneath (≤12 words), and a provenance chip (e.g. `CMHC · Oct 2025 · Toronto`) that opens the source.
- Optional simple visual when it adds meaning: a single bar or two-bar comparison (e.g. the listing's rent vs. the area benchmark). No pie charts, no multi-series charts, no tables.
- Easy on the eyes: calm background (dim the game-show stage), generous spacing, high contrast, no confetti or flashing. Gentle count-up animation; static under reduced motion.
- Uses the same `src/show/` shell and text rules as everything else.

### Skipping
- **Skip** button (and tap anywhere / Space / Enter) goes straight to the next question.
- Auto-advances after ~5 seconds unless the player taps "Hold" to keep reading.
- Settings toggle: **Show stats: on / off**. Off removes stat cards entirely.
- Demo preset: stats on, auto-advance shortened to ~3 seconds.

### Content rules
- **Every stat is a real, sourced Toronto (or Ontario/Canada, clearly labelled) figure** stored as a `Field` (`PRD.md` §8) with value, unit, geography, reference period, source URL and status `measured` or `derived`. Never `illustrative`: a stat card must not show a made-up number.
- Each stat is linked to the specific question it follows and must be relevant to that question's lesson.
- **No sourced stat for a question → no stat card.** Don't pad with loosely related numbers.
- Geography and year are always visible on the card. Different sources aren't combined into one figure.
- Stat cards don't affect score.

Data shape:

```ts
type StatCard = {
  id: string;
  question_id: string;      // the question it follows
  label: string;            // ≤12 words
  stat: Field<number>;      // PRD.md §8; status must be "measured" or "derived"
  compare_to?: Field<number>; // optional second bar
  verified_by: string;
};
```

Stored in `data/stats.json`.

### Candidate stats for the Base game (all to be sourced and verified)

| Round | Candidate stat | Likely source | Status |
|---|---|---|---|
| Spot the Fake | Rental/housing fraud reports or losses in Canada or Ontario | Canadian Anti-Fraud Centre or police data | To source |
| Pick Your Place | Average rent for the offer's area | CMHC Rental Market Survey, Toronto survey zone | Data identified |
| Pick Your Place | Share of renter households spending 30%+ of income on shelter in the neighbourhood | 2021 Neighbourhood Profiles | Data identified |
| Pick Your Place | TTC adult fare and monthly fare cap | TTC fare pages (`PRD.md` §6) | Sourced |
| Move-In Day | Something documented about deposits/disputes, if an official figure exists | Landlord and Tenant Board reports | To source; skip if none |
| Something Breaks | Apartment building evaluation results (e.g. share of buildings below a score threshold) | RentSafeTO / Apartment Building Evaluation open data | Data identified |

### Timing
The Base game target (Change 1) is measured **with stat cards on** and auto-advancing. If it runs over 3 minutes, cut stats to the strongest 3–4, not the questions.

### Acceptance criteria
- [ ] A stat card appears after the feedback of every question that has a verified stat, and not after questions without one.
- [ ] Skip, tap-anywhere, Space/Enter, auto-advance and Hold all work; "Show stats: off" removes all cards.
- [ ] Every card shows geography, period and a working source chip; no card shows an `illustrative` value (test on `data/stats.json`).
- [ ] Number is the largest element on screen and readable at 375px width; no layout shift during the count-up.
- [ ] Reduced motion: no count-up animation, number appears static.
- [ ] Base demo preset still finishes in ≤3 minutes with stats on.
